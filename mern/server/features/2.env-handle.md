# Environment Variables স্মার্টলি Handle করা

## Step 1: `.env` আর `.env.example` file বানানো

প্রজেক্টের root-এ দুটো **file** বানাব:

- **`.env`**: এখানে আসল value থাকবে (password, database URL ইত্যাদি)। এটা কখনো GitHub-এ push হবে না।
- **`.env.example`**: এখানে শুধু sample রাখব, যাতে অন্য developer বুঝতে পারে কোন কোন variable লাগবে। এটা GitHub-এ push হবে।

`.gitignore`-এ শুধু `.env` লিখব, `.env.example` লিখব না:

```gitignore
.env
```

---

## Step 2: `.env` file-এ variable দেওয়া

```env
PORT=5000
DB_URL=mongodb://localhost:27017/my-database
NODE_ENV=development
```

`.env.example`-এ একই key থাকবে, কিন্তু আসল value থাকবে না:

```env
PORT=5000
DB_URL=your_database_url_here
NODE_ENV=development
```

> **Note: `NODE_ENV`-এর value কী কী হতে পারে?**
> Node.js নিজে কোনো value ঠিক করে দেয় না, এটা একটা convention। সাধারণত তিনটা value ব্যবহার হয়:
>
> - `development`: নিজের computer-এ কাজ করার সময়
> - `production`: live server-এ app চালানোর সময়
> - `test`: test চালানোর সময়

---

## Step 3: `dotenv` install করা

`.env` file থেকে value পড়ার জন্য `dotenv` package লাগবে:

```bash
npm install dotenv
```

## Step 4: Config file বানানো

সব env variable এক জায়গা থেকে handle করার জন্য `src/app`-এর ভিতরে `config` নামে একটা folder বানাব, আর তার ভিতরে একটা file:

`src/app/config/env.ts`

```ts
import dotenv from "dotenv";

dotenv.config();

type NodeEnv = "development" | "production" | "test";

interface EnvConfig {
	PORT: string;
	DB_URL: string;
	NODE_ENV: NodeEnv;
}

const loadEnvVariables = (): EnvConfig => {
	const requiredEnvVariables: string[] = ["PORT", "DB_URL", "NODE_ENV"];

	// কোনো variable missing থাকলে app শুরুতেই বন্ধ হয়ে যাবে
	requiredEnvVariables.forEach((key) => {
		if (!process.env[key]) {
			throw new Error(`Missing required environment variable: ${key}`);
		}
	});

	// NODE_ENV-এর value ঠিক আছে কিনা check করা
	const allowedNodeEnvs: NodeEnv[] = ["development", "production", "test"];
	if (!allowedNodeEnvs.includes(process.env.NODE_ENV as NodeEnv)) {
		throw new Error(
			`Invalid NODE_ENV: ${process.env.NODE_ENV}. Allowed: ${allowedNodeEnvs.join(", ")}`,
		);
	}

	return {
		PORT: process.env.PORT as string,
		// eslint-disable-next-line @typescript-eslint/no-non-null-assertion
		DB_URL: process.env.DB_URL!,
		NODE_ENV: process.env.NODE_ENV as NodeEnv,
	};
};

export const envVars = loadEnvVariables();
```

### `as string` আর `!` এর পার্থক্য

`process.env`-এর প্রতিটা value-র type হলো `string | undefined`। কিন্তু আমরা উপরে আগেই check করে নিয়েছি যে value আছে, তাই TypeScript-কে বলে দিতে পারি এটা `string`। দুইভাবে বলা যায়:

- `process.env.PORT as string`: type assertion দিয়ে
- `process.env.DB_URL!`: `!` (non-null assertion / bang sign) দিয়ে

দুটোর কাজ একই। তবে আমাদের ESLint-এর `strict` config-এ `!` ব্যবহার করলে error দেয়, তাই উপরে `eslint-disable-next-line` comment দিতে হয়েছে। এজন্য `as string` ব্যবহার করাই সহজ।

> **খেয়াল রাখো:** `as` বা `!` শুধু TypeScript-কে বিশ্বাস করায়, আসলে কিছু check করে না। তাই আগে নিজে check করে নেওয়াটা জরুরি, যেটা আমরা `forEach` আর `allowedNodeEnvs` দিয়ে করেছি।

## Step 5: ব্যবহার করা

এখন থেকে কোথাও সরাসরি `process.env` লিখব না, সবসময় `envVars` import করে ব্যবহার করব:

```ts
import { envVars } from "./app/config/env";

app.listen(envVars.PORT, () => {
	console.log(`Server is running on port ${envVars.PORT}`);
});
```

এতে সুবিধা হলো:

- কোনো variable missing থাকলে app শুরুতেই error দেবে, পরে হঠাৎ crash করবে না।
- `envVars.` লিখলেই VS Code-এ autocomplete পাব, spelling ভুল হবে না।
- সব env variable এক জায়গায় থাকায় manage করা সহজ।
